# Repo Guidance: Abraham2748

## Repo Identity

This repo has two unrelated concerns. Do not conflate them:

1. **`README.md`** — a public GitHub profile card (rendered on the GitHub profile page). Prose/markdown content aimed at human visitors.
2. **Shell config files** (`.bashrc`, `.bashrd-wsl`, `.zshrc`) — personal environment setup for the repo owner's own machines. Shell scripts aimed at interactive shell sessions.

This is a personal dotfiles + profile repo, not an application, library, or service. There is no build step, no test suite, no deploy pipeline, and no CI to satisfy.

## Editing Conventions / Gotchas

- **Never break the interactive-shell guard in `.bashrd-wsl`.** Near the top of the file:
  ```bash
  case $- in
      *i*) ;;
        *) return;;
  esac
  ```
  This is the stock Debian guard that makes non-interactive shell invocations return early. Removing, moving, or altering it will break non-interactive shell invocations (e.g. `scp`, some CI/tooling that shells out non-interactively).

- **The `pull` alias intentionally differs between bash and zsh.** In `.bashrc` it is `git fetch && git rebase`; in `.zshrc` it is plain `git pull`. This is intentional, not a bug or inconsistency to reconcile. Never "fix" or unify these two definitions unless the user explicitly asks for that change.

- **Hardcoded personal values are intentional.** Project paths, the AWS MFA profile name, and the personal email address appear as literal values throughout the shell configs. Never genericize, redact, or template-ize any of these without an explicit user request.

- **Section-header convention.** Sections in the shell configs use banner-style headers:
  ```bash
  # ---------------------------------------------------------------
  # Section Name
  # ---------------------------------------------------------------
  ```
  Individual aliases carry inline trailing comments explaining what they do. Match this style when adding new aliases or sections.
